## 1. modernc.org/sqlite driver symbol — ANSWERED

`Driver` is an exported struct. Registration is one line:

```go
func init() { sql.Register("sqlite3", &sqlite.Driver{}) }
```

`modernc.org/sqlite` also exports `NewConnector(dsn string) (driver.Connector, error)` if a
connector is ever needed instead.

**Change to Task 4:** the plan's `sqlited` package does **not** need a custom `Open` method to
force `PRAGMA foreign_keys`. The DSN handles it (finding 2). Drop the wrapper type; register
`&sqlite.Driver{}` directly.

## 2. DSN pragma syntax — ANSWERED

This exact form works, verified by reading the pragmas back:

```text
file:<path>?_pragma=journal_mode%28WAL%29&_pragma=busy_timeout%285000%29&_pragma=foreign_keys%28ON%29
```

Built with `url.Values` and three `Add("_pragma", ...)` calls, exactly as the plan's
`FileDSN` does. Read back after `Ping`:

| Pragma | Value |
|---|---|
| `journal_mode` | `wal` |
| `busy_timeout` | `5000` |
| `foreign_keys` | `1` |

**Bonus:** `CREATE VIRTUAL TABLE t USING fts5(...)` succeeds — FTS5 is compiled in, so M7
search needs no additional dependency. Confirms spec decision D4.

## 3. Does keyring reintroduce cgo? — ANSWERED, and it is more subtle than the plan assumed

**Building is fine.** With `CGO_ENABLED=0`, `keyring` + `modernc.org/sqlite` compile cleanly for
all four targets:

| Target | Result |
|---|---|
| `darwin/arm64` | OK |
| `linux/arm64` (the NAS) | OK |
| `linux/amd64` | OK |
| `windows/amd64` | OK |

**But the macOS Keychain backend is cgo-gated and vanishes silently:**

```text
CGO_ENABLED=0   available backends: [pass file]
CGO_ENABLED=1   available backends: [keychain pass file]
```

The build does not fail. `keyring.Open` does not fail. The token simply lands in an encrypted
file instead of the macOS Keychain, with no diagnostic. This is the same
non-deterministic-backend hazard the spec warned about (§7), arriving through a different door
than expected.

**Changes to Task 10:**

1. Build matrix is now explicit: **macOS dev builds use `CGO_ENABLED=1`** to get Keychain;
   **cross-compiled Linux release builds use `CGO_ENABLED=0`** and get secret-service or file.
   This costs nothing — `modernc.org/sqlite` is pure Go either way, so CGO being on for a mac
   build does not make the mac binary cgo-dependent for SQLite.
2. `NewKeyring` must **report which backend it selected** rather than silently accepting a
   fallback. A user who believes their refresh token is in the Keychain when it is in a
   passphrase-protected file has been misled about their own security posture.
3. The plan's Task 10 Step 6 check (`CGO_ENABLED=0 ... go build ./...` succeeds) is necessary
   but **not sufficient** — it passes here and would not have caught this. Add an assertion on
   `keyring.AvailableBackends()` per platform.

## 4–8. Mail-access questions — RESCOPED to IMAP, no longer blocked

The connector is IMAP rather than the Gmail API (spec §6, D12), so these need an app password
on a throwaway Gmail account with 2FA enabled — not a Google Cloud project.

- **4. Do stored and appended bytes hash-match?** The thesis.
- **5. Observed FETCH throughput**, and where the 2,500 MB/day cap bites. IMAP is
  bandwidth-bound, so record MB/minute and average message size.
- **6. Does `APPEND` store the bytes unmodified,** or does Gmail rewrite headers?
- **7. Does Gmail advertise `CONDSTORE` after authentication?** It does not before —
  verified against `imap.gmail.com` on 2026-09-08. Without it, M3 falls back to `UIDNEXT`
  scanning.
- **8. Do `X-GM-MSGID` / `X-GM-THRID` / `X-GM-LABELS` behave as documented** on a real mailbox?
- **9. Is the API message id the hex form of `X-GM-MSGID`?** The two-connector plan (spec §6)
  depends on both transports producing the same `external_id`. If they differ, switching
  transports means re-ingesting the mailbox.
- **10. Can a Go IMAP client issue raw `X-GM-*` fetch items?** `emersion/go-imap/v2@beta.8`
  has no `X-GM` support — verified by inspecting the module — so this is needed either way.

### Verified 2026-09-08 against imap.gmail.com

| Capability | Advertised pre-auth |
|---|---|
| `IMAP4rev1` | yes |
| `X-GM-EXT-1` | yes |
| `AUTH=XOAUTH2` | yes — so the credential is pluggable; IMAP does not force app passwords |
| `CONDSTORE` | no |
| `QRESYNC` | no |
